# StructLens v0.4 — Structural Reliability and Pocket Evidence

**Status:** implementation specification  
**Date:** 2026-08-30  
**Target:** StructLens v0.4.0  
**Author:** Adriano Marques Gonçalves (UNIARA), with implementation assistance from Codex

## 1. Purpose

StructLens v0.4 will turn the existing pairwise structural comparison engine into
an auditable structural-evidence workbench. The release will add coordinate
quality screening, native geometric pocket detection, parameter-aware free-volume
measurement, and mutation-to-pocket comparison while completing the currently
disconnected v0.3 workflow in the GUI, reports, command line, and PyMOL companion
plugin.

The scientific claim is deliberately bounded. StructLens will report reproducible
geometric observations and concordance between independent evidence channels. It
will not infer binding affinity, pathogenicity, thermodynamic stability, catalytic
function, or mutation causality from coordinates alone.

The product-level novelty is the integrated workflow: one immutable report links
coordinate QC, authoritative residue correspondence, local structural change,
pocket persistence, parameter sensitivity, lining-residue changes, interactions,
and provenance without collapsing them into an opaque probability. The individual
geometric methods are literature-derived and must not be advertised as new
algorithms.

## 2. Existing foundation and defects to correct first

StructLens v0.3 already provides PDB/mmCIF parsing, sequence/manual/US-align
mapping, mutation descriptors, strict and refined RMSD, interaction comparison,
MSA/conservation, distance-difference maps, displacement vectors, site metrics,
FreeSASA integration, exports, and a validated data-only PyMOL bundle.

The audit found correctness and delivery gaps that must precede new science:

- the GUI does not orchestrate most v0.3 services after a normal comparison;
- v0.3 export payloads are manually staged and not part of a canonical report;
- site-fitted "backbone RMSD" currently uses only C-alpha atoms;
- site metrics may be calculated without an authoritative transform;
- fewer than four atoms can be reported as a zero envelope volume instead of
  unavailable;
- difference-map construction can pass NaN values into a model that rejects them;
- normalized atoms omit B-factors and source identity, while ligands, ions, and
  protein residues are not represented as distinct component classes;
- the GUI controller is a monolith and its release-critical flow is effectively
  untested;
- SciPy is used for geometry but is not declared as a runtime dependency;
- identical-input comparison can misclassify the nonstandard residue MSE as a
  mutation, so identity must use authoritative residue identity rather than a
  lossy one-letter fallback;
- external backends and compressed/large inputs lack consistent time, atom,
  decompressed-size, and output-size limits;
- the measured atomic convex hull is correctly documented as an atomic envelope,
  but users have no actual cavity/free-volume measurement.

These are v0.4 Phase 0 defects, not optional cleanup.

## 3. Scientific invariants

1. Missing, invalid, not applicable, not detected, and numerical zero are distinct
   states. No layer silently converts one into another.
2. A pocket is a geometric hypothesis. A detected pocket is not automatically a
   ligand-binding site, druggable site, or functional site.
3. Atomic-envelope volume and pocket free volume remain separate quantities with
   separate names, units, methods, and provenance.
4. Reference-to-target deltas always mean `target - reference` and use the same
   parameters on both structures.
5. A structure difference is not evidence that a mutation caused the difference.
6. Coordinates are never modified to make validation pass. Raw inputs are hashed,
   and derived transforms are stored explicitly.
7. The asymmetric unit/as-file model and a biological assembly are not
   interchangeable. v0.4 reports the analyzed representation and does not claim
   biological assembly construction unless it was actually performed.
8. Screening QC is not crystallographic model-to-data validation. Without
   diffraction data, StructLens must not claim R-factor, real-space correlation,
   or full MolProbity equivalence.
9. Approximate all-heavy-atom clashes without added hydrogens are labeled exactly
   as such; they are not called a MolProbity clashscore.
10. Every numerical result carries algorithm identity, semantic version,
    parameters, units, source hashes, and availability/warning state.
11. Analysis reads each bounded input once into an immutable content-addressed
    snapshot. Parsers, reports, exports, and PyMOL bundles use that snapshot or
    reject a later path whose hash changed.
12. Canonical scientific artifacts contain no wall-clock timestamp. Their stable
    IDs derive from canonical input selections, hashes, methods, and parameters;
    event timestamps are stored separately.

## 4. User workflow

### 4.1 Compare structures

The user opens a project, selects reference and target PDB/mmCIF files, chooses
models and chains, and runs one analysis. That action builds a single immutable
`AnalysisReport`; it must populate Structures, Sequences, Residues, Interactions,
Sites/Pockets, Charts, Results, Export, and PyMOL surfaces without manual staging.

### 4.2 Inspect coordinate quality

Before interpreting a comparison, the user sees a compact QC gate for each input:

- parse errors and parser warnings;
- analyzed model, chains, component counts, and source hash;
- non-finite coordinates and invalid occupancy/B-factor values;
- missing/duplicate backbone atoms and duplicate atom identities;
- alternate-conformer inventory and occupancy-sum warnings;
- peptide-chain continuity and C-alpha pseudo-geometry screening;
- heavy-atom overlap screening with the limitation stated in the UI.

Errors prevent dependent analyses. Warnings remain visible in reports and exports.

### 4.3 Detect and measure pockets

The user can run either:

- **blind detection** over selected protein chains; or
- **focused measurement** around a selected residue set, known ligand, or selected
  blind-pocket candidate.

Blind results are a ranked table of geometric candidates, never just a single
answer. Each candidate shows centroid, free volume in A^3, lining residues,
accessibility, component support, parameter stability, and QC flags. If no
candidate survives the declared filters, the result is `not_detected`, not zero.

### 4.4 Compare mutation-associated pocket changes

Reference and target candidates are matched by authoritative residue
correspondence. The report presents:

- unambiguous, ambiguous, and unmatched pocket identities;
- absolute and relative free-volume delta;
- coarse-versus-fine discretization sensitivity;
- lining-residue gains and losses;
- mutations/insertions/deletions among lining residues;
- local C-alpha and side-chain displacement;
- conserved, gained, and lost putative interactions;
- pocket presence and geometry evidence separately from known-ligand support;
- all unavailable/QC states.

The UI explicitly says that these are structural associations, not causal or
energetic predictions.

## 5. Domain architecture

### 5.1 Coordinate evidence and component identity

Extend the immutable parsing model without breaking the current public API:

- `AtomRecord`: atom name, element, coordinate, altloc, occupancy, B-factor,
  source serial/atom-site id, formal charge when available;
- `StructureComponent`: polymer residue, ligand, water, ion, or other;
- `StructureMetadata`: source format, selected model, available models, analyzed
  chains, experimental method/resolution when present, and assembly scope;
- `ParsedStructure`: normalized analysis structure plus retained components,
  metadata, raw source hash, and parser diagnostics.

Analysis continues to consume the normalized polymer structure. Pocket and ligand
services additionally consume retained components. Alternate conformers remain
identifiable even when one conformer is selected for the primary deterministic
analysis.

### 5.2 Stable input selection and evidence snapshots

Add an immutable `InputSelection` that identifies an input by SHA-256 content ID,
source format, selected model, author and label chain identifiers, alternate-location
policy, and assembly scope. A display path is metadata, not identity. Two files with
the same basename but different bytes remain distinct.

An analysis starts from a bounded `SourceSnapshot`. Saving a project persists the
snapshot in a content-addressed evidence directory or records an explicitly external
source plus its required hash. Export never re-reads an unverified mutable path.
Model selection is explicit; v0.4 does not silently choose the first model.

### 5.3 Typed availability and provenance

Introduce reusable immutable contracts:

- `Availability`: available, not_applicable, not_detected, invalid_input,
  dependency_unavailable, numerical_failure;
- `Diagnostic`: stable code, severity, message, affected source/atom/residue, and
  remediation hint;
- `MethodProvenance`: method id/version, parameters, units, backend versions,
  input hashes, analyzed representation, and deterministic artifact id;
- `AuditEvent`: optional wall-clock time and user/workstation event context, stored
  outside canonical scientific serialization.

User-facing text is derived from stable codes; scientific services do not return
free-form GUI strings as their main contract.

### 5.4 Coordinate QC

Create `core/quality` pure functions and an application orchestration service.
Initial v0.4 checks are deterministic and require no proprietary backend:

- finite coordinate validation;
- occupancy and B-factor range/finite checks;
- alternate-location occupancy-sum diagnostics;
- duplicate atom identity and missing backbone inventory;
- peptide C-N continuity and C-alpha distance screening;
- unknown element/radius diagnostics;
- spatial-indexed heavy-atom overlap screening.

Ramachandran, rotamer outlier, hydrogen placement, crystallographic density, and
exact MolProbity-compatible scoring are deferred until versioned reference data
and validation fixtures are included. The UI may explain this limitation but must
not show placeholder scores.

### 5.5 Pocket domain

Create `core/pockets` with immutable types:

- `PocketDetectionSettings`;
- `PocketSphere`;
- `PocketCandidate`;
- `PocketMeasurement`;
- `PocketMatch` and `PocketComparison`;
- `PocketAnalysis` containing availability, diagnostics, candidates, and
  provenance.

`SiteDefinition` continues to represent an explicit biological selection.
`PocketCandidate` represents a detected geometric region. A site may reference a
pocket candidate, but the types are never aliases.

### 5.6 Canonical analysis report

Create an immutable `AnalysisReport` assembled by an application service from:

- pairwise/multi-structure `AnalysisResult`;
- input QC reports;
- MSA and conservation when requested;
- interactions and interaction differences;
- site metrics;
- pocket analyses and pocket comparisons;
- distance-difference matrix and displacement vectors;
- Evidence Cards;
- typed availability, diagnostics, and method provenance.

GUI, CLI, project persistence, JSON/XLSX/CSV/TSV, and PyMOL bundle serialization
all consume this report. Arbitrary `Mapping[str, Any]` staging is retained only as
a temporary read-compatibility boundary and then removed from the primary path.
Before construction, mutable legacy objects such as `ResidueCorrespondence` are
converted to deeply immutable value snapshots. Mutating a working object cannot
change a report ID, hash, or serialized report.

## 6. Native pocket algorithm

### 6.1 Detection

The native detector is a clean-room implementation based on the published
Voronoi/Delaunay alpha-sphere concept used by fpocket, not copied source code.

1. Select finite heavy atoms with known van der Waals radii from the chosen protein
   chains.
2. Build a SciPy Delaunay tessellation of atom centers.
3. For each tetrahedron, solve its circumsphere robustly and reject degenerate or
   non-finite cases.
4. For every candidate center, calculate clearance exactly as
   `min_i(distance(center, atom_i) - vdw_radius_i)` over all spatially relevant
   atoms using an indexed query. The four Delaunay vertices alone are insufficient
   when atom radii differ. Reject a center intruded by any non-vertex atom and
   retain clearances only within the declared range/radii-table version.
5. Mark spheres as apolar/polar from neighboring atom chemistry using explicit,
   tested rules.
6. Cluster overlapping/nearby spheres with a deterministic graph/union-find
   algorithm.
7. Remove clusters below declared sphere/volume/support thresholds.
8. Derive centroid, lining atoms/residues, and ranking components.
9. Classify solvent connectivity on a separately parameterized free-space grid:
   inflate protein radii by the probe radius, flood-fill free boundary cells, and
   label candidate cells connected to outside solvent as open. Candidate regions
   without such connectivity are closed cavities. Mouth cells are the interface
   with outside-connected free space. Grid spacing, probe radius, boundary margin,
   and approximate mouth area are reported.

The ranking is transparent: volume support, alpha-sphere count, buriedness,
polarity balance, and parameter persistence are separate displayed components.
There is no trained ligandability probability in v0.4.

### 6.2 Free-volume measurement

For each candidate or focused region:

1. Bound the union of accepted alpha spheres plus a declared margin.
2. Use the input Cartesian frame. Set the grid origin to the component-wise region
   minimum minus margin and sample cell centers at
   `origin + (index + 0.5) * spacing`. Translation is preserved; rotation can change
   the discretized count and is assessed as bounded numerical sensitivity rather
   than falsely claimed invariant.
3. Retain points inside at least one pocket sphere.
4. Apply an explicit component policy. `protein_only` excludes protein van der
   Waals spheres and measures the geometric void even in a holo structure.
   `unoccupied` additionally excludes selected retained non-water components. The
   policy is provenance and cross-policy deltas are forbidden.
5. The operational free volume is `N_free * spacing^3` A^3.
6. Run a coarse and fine grid by default (1.0 A and 0.5 A). Absolute sensitivity is
   `|V_fine - V_coarse|`; relative sensitivity divides by `V_fine` only when it is
   positive. If both volumes are zero, absolute sensitivity is zero and relative
   sensitivity is unavailable, avoiding an invented `0/0` value.
7. Enforce a hard voxel cap and return a typed numerical-limit state with suggested
   remediation instead of exhausting memory.

The full settings and radii table version are serialized. Volume comparisons are
disabled when method-defining settings differ.

### 6.3 Pocket matching and comparison

Candidate matching uses reference-position lining-residue overlap plus transformed
centroid distance. A configurable bipartite assignment produces:

- `matched` when the optimum is unique and passes thresholds;
- `ambiguous` when alternatives are within a declared score margin;
- `unmatched_reference` or `unmatched_target` otherwise.

Ambiguity is retained and exported. The algorithm never silently chooses the
nearest centroid alone.

### 6.4 Known-ligand validation

Retained non-polymer components permit ligand-supported evaluation. Water and a
versioned list of common crystallization ions/buffers are excluded by explicit
component rules. For eligible ligands, StructLens reports ligand-center distance,
ligand atom coverage by the candidate volume, and lining-residue overlap.
Ligand support affects evidence presentation, not the geometric measurement.

## 7. Site metrics corrections

- Site strict RMSD uses matched N, C-alpha, C, and O atoms when available, with
  per-residue completeness recorded.
- Site-fitted RMSD applies a proper Kabsch fit to the declared backbone atom set.
- Global-frame site RMSD is unavailable if no authoritative global transform is
  present.
- Atomic-envelope volume returns unavailable for fewer than four non-coplanar
  heavy atoms or a numerical hull failure.
- Existing field names and documentation retain "atomic envelope" wording.
- Per-site SASA is added only when the FreeSASA backend returns atom/residue areas;
  whole-structure total area is never relabeled as site SASA.

## 8. Structural Evidence Concordance

The Results and Evidence Card views present a concordance panel with independent
channels:

- geometry detected;
- support from a known ligand, if one exists;
- persistence across declared detector settings;
- coarse/fine volume sensitivity;
- lining-residue correspondence and pocket-match ambiguity;
- local coordinate QC;
- interaction persistence;
- ensemble persistence is explicitly unavailable in v0.4; model-wise aggregation
  remains deferred until its weighting and non-independence semantics are defined.

Each channel is available/warning/unavailable with its native measure. v0.4 does
not calculate a universal combined score. This avoids false precision while giving
the user a reproducible, unusual, and scientifically inspectable synthesis.

## 9. GUI design

Preserve the restrained evidence-workbench visual language. Refactor the Qt layer
into focused presenters/controllers before adding dense controls.

- Add a scroll container to every scientific page.
- Replace duplicate Compare actions with one primary action and progress/cancel.
- Add a **Quality** page before interpretation pages.
- Rename **Sites** to **Sites & Pockets**, with two tabs:
  - explicit sites;
  - detected pockets and comparisons.
- Candidate table prioritizes ID, status, volume, sensitivity, centroid,
  accessibility, lining count, and warnings; a detail drawer carries the remaining
  evidence instead of a 15-column table.
- Add **Detect pockets** and **Measure selected pocket** actions with parameter
  presets and an advanced section.
- Every metric label includes units and a tooltip/"Method & limits" explanation.
- `None` is rendered as “Unavailable — reason”, never `0.000`.
- Selection is an immutable `AnalysisSelection` shared by tables, charts, Evidence
  Cards, and PyMOL.
- A normal Compare action populates all available v0.3/v0.4 pages from the canonical
  report.

The standalone GUI and in-PyMOL panel must expose the same scientific controls.
PyMOL-only actions remain disabled with a clear explanation in standalone mode.

## 10. CLI, persistence, exports, and PyMOL

### CLI

Add application-backed subcommands:

- `structlens compare ... --report report.json`;
- `structlens qc structure.cif`;
- `structlens pockets structure.cif --chain A`;
- `structlens pocket-compare reference.cif target.cif ...`.

The legacy compare invocation remains compatible for v0.4.

### Projects and exports

Bump the project schema with a migrator. Persist analysis settings, model/chain
selection, pocket settings, canonical report location/hash, and UI selection.
Export:

- canonical JSON with a versioned JSON Schema;
- XLSX with summary, QC, pockets, pocket comparison, lining residues, diagnostics,
  methods, and provenance sheets;
- tidy CSV/TSV tables for pockets and comparisons.

### PyMOL companion

Keep the existing safe data-only `.structlens-pymol` contract. Do not generate or
execute `.pml`/Python scripts. Extend the versioned bundle with validated optional
entries for QC, pocket candidates, pocket grid points/spheres, lining residues,
matches, and concordance. The separate `structlens-pymol` plugin will visualize
these entries as namespaced objects/selections and surfaces/CGO where supported.

Update the project-local PyMOL workflow skill with the new schema, evidence
semantics, validation scenarios, and no-execution security rule. Skill changes use
scenario-first tests as required by the Superpowers writing-skills workflow.

## 11. Validation strategy

### 11.1 Unit and property tests

Every scientific method is developed RED-GREEN-REFACTOR. Required invariants:

- rigid-body invariance for analytic detector geometry and bounded coarse/fine
  variation for axis-discretized volume/accessibility;
- deterministic reruns and deterministic ordering;
- missing-data preservation;
- parameter/provenance round-trip;
- finite-value and degeneracy handling;
- atom deletion and coordinate-noise sensitivity;
- voxel cap behavior;
- no-pocket behavior;
- reference/target delta sign;
- pocket-match ambiguity;
- identical-input zero delta only when both measurements are available.

Analytic fixtures include isolated spheres, overlapping spheres, tetrahedra,
sealed/open synthetic cavities, translated/rotated structures, and known grid
counts.

### 11.2 Curated structural fixtures

Pin source hashes, accession, biological/as-file scope, and retrieval date for:

- small parser/QC fixtures with occupancy, B-factor, alternate-location, duplicate,
  and multi-model cases;
- T4 lysozyme cavity mutants/controls where exact mutation backgrounds match;
- adenylate kinase `1AKE`/`4AKE` as a pinned holo/apo pair and `1E4V` for the
  exactly declared G10V comparison;
- `1CRN` PDB/mmCIF parity and rigid-transform validation;
- `1D3Z` to validate explicit multi-model handling;
- CavBench accession manifests for offline benchmark tooling.

Published pocket volumes are method-specific reference anchors, not exact expected
values for a different algorithm.

### 11.3 External agreement

Where licenses and reproducible installation permit, compare detection overlap and
volume trends against CASTp/fpocket/FreeSASA outputs. Record tool versions and
parameters. Do not bundle GPL or proprietary implementation code into StructLens.

Benchmark reporting includes detection precision/recall/F-score, known-ligand
coverage, runtime/memory, no-result rate, and parameter sensitivity. Performance
claims require a pinned dataset and generated report.

### 11.4 Product verification

- new/changed scientific modules: at least 90% branch coverage;
- repository: raise from the audited 53% baseline toward the required 80% by
  exercising real GUI/application flows, not excluding them from measurement;
- unit, integration, Qt GUI, CLI, export/schema, PyMOL bundle, and installed-package
  smoke tests;
- Ruff, mypy, dependency audit, license audit, diff review;
- Windows installer build and local installation into a dedicated test location;
- Linux build verification in CI or an available Linux runner;
- no GitHub push or release until the user tests the locally installed build.

## 12. Distribution and licensing policy

The StructLens source remains MIT. Official frozen v0.4 GUI artifacts use PySide6
under a documented LGPL compliance strategy and do not freeze PyQt5. PyQt5 remains
an explicit user-selected GPL-compatible extra rather than the default binary path.

MUSCLE 5 remains a separately invoked GPL-3 executable, never linked or copied into
StructLens source. Any official artifact that redistributes it must identify the
component separately, include the complete GPL-3 text, preserve copyright, provide
the exact corresponding-source route/archive required for that binary, and impose
no installer restriction on its GPL rights. The release gate verifies those files.
If this policy cannot be satisfied reproducibly, MUSCLE is removed from official
artifacts and treated as a user-supplied optional backend.

This engineering policy is conservative compliance work, not legal advice. No
dependency or bundled tool may cause the MIT project license to be represented as
the sole license governing an installer.

## 13. Performance and failure behavior

- Spatial queries use `scipy.spatial.cKDTree` or equivalent indexed access.
- Delaunay failures on coplanar/underspecified selections return diagnostics.
- Candidate and voxel limits are explicit settings with safe defaults.
- File byte size, decompressed byte size, model/atom/residue counts, backend wall
  time, and captured backend output have explicit limits with actionable failures.
- Long analyses run outside the Qt event loop, report stages/progress, and support
  cooperative cancellation.
- Cancellation never writes a partial canonical report as successful.
- Imported files are parsed as data only. No imported or generated script is
  executed.

## 14. Non-goals for v0.4

- affinity, free-energy, pathogenicity, or stability prediction;
- molecular dynamics simulation;
- cryptic-pocket claims from one static structure;
- exact MolProbity reproduction;
- automated protonation or hydrogen placement;
- de novo biological-assembly generation;
- copying or reverse engineering proprietary Maestro or Discovery Studio code;
- opaque ML ligandability scores;
- GitHub publication before local user acceptance.

## 16. Acceptance criteria

v0.4 is ready for local user testing only when:

1. a normal GUI comparison produces one canonical report and populates all
   applicable evidence views;
2. invalid coordinates fail safely with actionable QC diagnostics;
3. blind detection returns deterministic candidates or an explicit no-result state;
4. focused free-volume measurement reports units, parameters, dual-grid sensitivity,
   and provenance;
5. reference/target pocket comparison reports matched/ambiguous/unmatched states and
   mutation/lining changes without causal language;
6. atomic envelope and pocket free volume cannot be confused in UI or exports;
7. CLI, JSON/XLSX/CSV/TSV, project persistence, and PyMOL bundle agree with the
   canonical report;
8. standalone and PyMOL GUI flows remain responsive and tested;
9. the English manual explains the complete workflow, method, limits, and examples;
10. a locally installed Windows build passes a clean smoke test and is left ready
    for the user; GitHub remains unchanged until explicit approval.
